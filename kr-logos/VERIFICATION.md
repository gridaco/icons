# 검증 프레임워크 (Verification) — "모르는 기업을 어떻게 믿는가"

> 보조 문서. 독트린은 [README](./README.md), 출처 등급(T0~T4)·evidence·history 스키마도 거기 있음.
> 이 문서는 **사람이 로고를 못 알아보는 경우의 신뢰 판단 규칙**만 다룬다.

## 우리가 겪은 상황 (the problem)

샘플 15개 수집 중:

- **유명 기업**(삼성·카카오 등)은 렌더 후 사람이 "이거 맞아?"로 검증됐다.
- 실제로 그 덕에 **무신사 1차 오류를 잡았다** — 스토어 헤더의 '무진장 세일' 캠페인 붓글씨를 로고로 잘못 추출 → 렌더+사람 확인으로 걸러내고 진짜 'MUSINSA' 워드마크로 교체.
- **그러나 모르는 기업은 사람도 못 알아본다.** "이게 ○○의 현행 로고가 맞나?"를 recognition으로 답할 수 없다. → recognition은 **확장되지 않는다.**

## 원칙: 신뢰 = 알아보기 ❌ → 증거 체인 ✅

로고가 "맞다"의 근거를 **알아봄**이 아니라 **검증 가능한 사실 4가지**에 둔다. 전부 제3자가 링크를 눌러 재확인 가능해야 한다(auditable).

| 코드 | 기준 | 무엇을 확인 | 왜 recognition 불필요 |
| --- | --- | --- | --- |
| **A. 신원 앵커** | 도메인 = 그 법인이 맞나 | 공식 사이트 푸터의 **사업자등록번호 / 법인명 / 대표자**를 타깃 법인과 대조. 가능하면 **DART 고유번호·종목코드**로 교차. | 네임세이크·계열사 오인을 *객관적 ID*로 차단 (예: 'JVM' 동명 해외기업 함정) |
| **B. 출처 권위** | 그 법인의 현행 공식 채널인가 | 로고를 **법인 자기 도메인의 라이브 자산(T0/T1)**에서 포착. 사이트 자체가 권위. | 공식 사이트가 지금 쓰는 마크 = 정의상 현행 공식 |
| **C. 교차 확인** | 독립 출처 ≥2개가 일치하나 | 공식 헤더 + (공식 뉴스룸/프레스 이미지 ∥ DART 첨부 ∥ 브랜드가이드 ∥ 앱스토어 아이콘) 중 **둘 이상에서 동일 마크** | 둘 이상이 같다면 알아보지 않아도 신뢰 가능 |
| **D. 현행성** | 폐기된 구버전 아닌가 | 라이브 서빙 + **마지막 리브랜드 일자/자산 수정일**과 정합 (`history`) | 시점이 사실로 고정됨 |

## 결정 규칙 (decision rule)

- **confidence high** — A(신원 확정) + B(T0/T1) + **C(≥2 독립 출처 일치)** 모두 충족.
- **confidence medium** — A + B 충족하나 C가 단일 출처거나, 파생(예: dark 색 변형) 자산.
- **confidence low / needs-review** — A 미확정(신원 불명) ∥ T3·T4만 ∥ 출처 간 상충 ∥ open_questions 잔존.
- **절대 금지** — **A(신원) 미확정 자산은 커밋하지 않는다.** 모르는 기업일수록 A가 먼저다.

## 무신사 케이스가 규칙으로 걸리는 이유

캠페인 붓글씨('무진장')는 (C)와 **이름 정합**에서 탈락한다:

- (C) 교차 확인 실패: 코퍼레이트 사이트·프레스·브랜드가이드엔 없고 **시즌 스토어 한 곳에만** 등장.
- 이름 정합 실패: 마크('무진장')가 **법인 브랜드명('무신사/MUSINSA')과 무관**.

→ recognition 없이도, "단일 출처 + 이름 불일치 = 신뢰 불가"로 자동 탈락. 진짜 로고는 헤더+about+프레스에서 **반복 등장**해 (C)를 통과한다.

## 사람의 역할 재정의

- ❌ "이 로고 알아보세요?" (모르는 기업엔 무용)
- ✅ "이 **증거 체인**(A·B·C·D 링크)이 성립하나?" — PR 리뷰어가 링크를 눌러 재확인.
- 즉 인간 검증은 **인식**이 아니라 **감사(audit)** 로 이동. 자동화 못 하지만, 누가 봐도 같은 결론에 도달하는 *규격화된 근거*가 있으면 신뢰가 성립한다.

## 수집 시 추가 절차 (기존 워크플로우에 끼워넣기)

1. 조사 단계에서 **A를 먼저** 확정 — 공식 도메인 푸터의 사업자등록번호/법인명을 캡처해 `evidence`에 `type: identity-anchor`로 기록.
2. 다운로드 후 **C** 위해 최소 1개의 독립 2차 출처(프레스/DART/앱)에서 동일 마크 확인 → `evidence` 추가.
3. confidence는 위 규칙대로 기계적으로 매긴다(자의적 'high' 금지).
4. C를 못 채우면 `needs-review`로 두고 커밋(자산은 보존, 신뢰만 보류).
