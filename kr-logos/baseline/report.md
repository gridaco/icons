> 가능한가"를 독트린(T0~T4) 기준으로 정성 평가. 2026-06-14.
> 입력: [`sample.csv`](./sample.csv). 방식: 다운로드 없이 출처 탐색·판정만.

## 결론 한 줄

**15개 중 14개 POSSIBLE, 1개 HARD(JVM), IMPOSSIBLE 0.** 확보 가능성은 예상보다
높지만, **"공식 채널의 다운로드 가능한 벡터(T0)"는 오히려 드물고**, 실제
주력 경로는 **브라우저로 사이트의 inline SVG를 추출(T1)** 하거나 **유명
워드마크는 위키미디어 PD SVG(T3)** 였다.

## 핵심 발견 (예상과 다른 점)

1. **"대기업이 쉽다"는 틀렸다.** 삼성·현대·LG·카카오는 **공식 자가배포 벡터가
   없고**, 공식 채널은 래스터 PNG거나(카카오는 비상업 제한) 한다. 실제로는
   **위키미디어 PD(저작권 문턱 미달 워드마크)** 가 워크호스. → 유명할수록 T3 PD에
   의존, 단 **상표권은 살아있음**.

2. **"무명 딥테크 스타트업이 어렵다"도 틀렸다.** 씨드로닉스·메디웨일·메이사는
   현대적 웹스택(WordPress/Webflow/Next.js)을 써서 **헤더 로고를 inline SVG로
   직접 서빙** → 브라우저로 긁으면 T1 깨끗한 벡터. 오히려 제일 쉬운 축.

3. **진짜 어려운 건 "레거시 래스터 사이트의 B2B 제조사".** JVM은 PNG뿐 + 같은
   분야 코맥스는 SVG가 있었음 → 난이도는 업종이 아니라 **사이트가 언제 만들어졌나
   (모던 스택 vs 옛날 정적 사이트)** 에 좌우됨.

4. **네임세이크(동음이의) 함정.** JVM의 모든 제3자 "JVM" 벡터는 무관한 해외
   기업(Jung von Matt 등). 짧은 이름·이니셜 기업은 **stock_code/DART로 먼저
   엔티티를 고정**하지 않으면 엉뚱한 로고를 수집할 위험.

5. **현행성(currency)이 큰 리스크.** LG(2023)·무신사(2025-10)·당근(2023) 리브랜드
   → 제3자 사이트는 **구버전 캐시**. 반드시 **라이브 공식 사이트와 대조**.

6. **SPA는 fetcher로 안 읽힌다.** 컬리·무신사는 JS SPA라 단순 fetch로 inline SVG
   추출 실패 → **실제 브라우저 렌더링 필요**. (독트린의 "브라우저로 다운로드"가
   바로 이 이유)

## 방법론에 주는 시사점 (다음 단계)

- **주력 수집기는 "브라우저 inline-SVG 추출(T1)".** 모던 사이트 다수에 통함.
  실제 브라우저(Claude in Chrome / Playwright)가 필수 — fetch로는 SPA를 못 읽음.
- **수집 전 엔티티 고정 단계 필수.** 한글명+영문명+stock_code+DART 고유번호로
  대상을 못 박고, 해외 네임세이크를 배제.
- **현행성 검증 강제.** 최종 자산은 항상 라이브 공식 사이트와 시각 대조. 제3자
  캐시 단독 신뢰 금지(특히 최근 리브랜드 기업).
- **라이선스 ≠ 가용성.** 카카오처럼 "벡터는 있으나 비상업 제한"이 존재 →
  provenance에 `trademark_owner`/사용제한 기록.
- **하드 테일 대응 경로 필요.** 레거시 래스터 전용(JVM류)은 T4 재구성 또는
  KIPRIS 도형상표/DART 첨부 이미지(여전히 래스터) → 벡터화 파이프라인 준비.
- **포맷 변환 스텝.** T0라도 .ai/.eps(야놀자)는 SVG 변환 단계 포함.

## 샘플 설계 회고

쉬움/중간/어려움 티어가 **확보 난이도와 잘 안 맞았다** — 난이도의 진짜 축은
"대기업 vs 스타트업"이 아니라 **(a) 사이트 모던함 (b) 이름 고유성 (c) 최근 리브랜드
여부**. 다음 대량 리스트는 이 3축으로 분류·표본추출하는 게 더 유용.
